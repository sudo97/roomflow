# ADR-0001: Модульний моноліт для домену бронювання

Статус: прийнято (ЛР1), переглянуто (ЛР12)

## Контекст
RoomFlow — SaaS для малих готелів (multitenancy). Команда невелика, домен бронювання, ціноутворення
і доступності тісно пов'язані транзакційно (перевірка конфлікту і створення бронювання).

## Рішення
Bounded context "Бронювання" (booking + store + httpapi) реалізовано одним сервісом із жорсткими межами
пакетів, які перевіряються архітектурним тестом (fitness function). Веб-інтерфейс виділено в окремий
сервіс frontend, оскільки він має інший цикл релізів (blue-green, ЛР12).

## Наслідки
+ атомарність бронювання без розподілених транзакцій (saga не потрібна);
+ поведінковий аналіз (Charlie, ЛР12) показує, що booking/httpapi/store змінюються разом — це один контекст;
− масштабування лише цілим сервісом; кандидат на виділення — календар доступності (read model, cache-aside).
